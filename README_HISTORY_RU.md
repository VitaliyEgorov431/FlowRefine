# FlowRefine — CPU pilot

Актуальная версия для защиты с CPU- и GPU-экспериментами:
**`submission/defense_v3/FlowRefine_Defense_EN_final.pptx`** — 10 основных слайдов
на английском и 3 справочных. Русский доклад на 7–8 минут:
`submission/defense_v3/DEFENSE_SPEECH_RU.md`; текст также включён в заметки слайдов.
Мотивация связана с нефтегазовой специальностью; экспериментальные данные остаются
общими синтетическими процессами. Замена только VLM на Qwen2.5-VL-3B FP16 дала
5/15 точных графов в B2 и B3 против прежних 9/15 и 7/15. Это поисковый повтор
на тех же задачах, исходные результаты не заменены.

Предыдущая презентация с реальными примерами: **`submission/examples_v2/FlowRefine_Defense_Examples.pptx`**
(13 слайдов). Слайды 4, 10 и 11 показывают корректное ветвление, регрессию
после редактирования и частичное исправление цикла. Использованы сохранённые PNG
с увеличением важных фрагментов; значения метрик взяты из результатов теста.

Дополнение `followup_v1` расширяет сохранённый пилот двумя поисковыми режимами:
**C0** — редактирование без внешних замечаний, **L3** — исправление только координат
по сохранённой комбинированной критике. Исходные `test_v1`, отчёт и презентация
сохранены. Дополнение выбрано после просмотра теста и не является новым независимым тестом.

Сравнение шести режимов: `demo/followup.html`. Новые материалы:
`submission/followup_v1/report_followup.pdf`, `report_followup.md` и
`FlowRefine_Defense.pptx`. Исходная галерея находится в `demo/index.html`.

Итог дополнения: C0 сохраняет все 15 семантических оценок B0; пересмотренный L3
тоже сохраняет семантику (11/15 точных графов), но геометрия не улучшилась:
0 задач лучше, 13 без изменения, 2 хуже. Среднее число ошибок L3 — 0.467
против 0.333 у B0. Первая неудачная версия L3 и её затраты сохранены отдельно.

Генерация редактируемых блок-схем из описания процесса и один раунд исправлений
по программной, визуальной или комбинированной обратной связи.

Проект запускается **без GPU, платного API и ключей**. Локальные модели работают
через `llama-cpp-python`; сохранённые результаты можно просматривать полностью
офлайн без загрузки моделей. Генерация схем — это вывод JSON текстовой моделью
и детерминированный рендеринг в SVG/PNG, а визуальный критик получает именно PNG.

## Быстро показать результат

Из каталога проекта:

```powershell
Invoke-Item ./demo/index.html
```

Команда открывает существующий `demo/index.html`. Если файл ещё не создан,
соберите галерею командами из раздела воспроизведения ниже.
Инференс при просмотре не запускается. В галерее можно выбрать задание и режим,
посмотреть до/после, замечания и скачать редактируемые SVG и JSON.

Наличие галереи не доказывает завершение эксперимента: недоступные режимы
помечаются явно. Фактическое покрытие указано в `analysis/test_v1/SUMMARY.md`
и `aggregate.json`, если эти файлы уже созданы. Отсутствующие результаты не
заменяются искусственными примерами или нулевой оценкой.

## Новый процесс из своего описания

После установки CPU-runtime и загрузки трёх основных файлов моделей:

```powershell
$env:PYTHONPATH = 'src'
.venv\Scripts\python.exe -m flowrefine.cli ask 'Create a flowchart: Start, Receive request, Check documents, Approve request, Send confirmation, Finish. Connect these six stages in order.' --output runs/custom_example
Invoke-Item ./runs/custom_example/index.html
```

Это новый настоящий CPU-инференс, который занимает время. Команда генерирует
схему, выполняет три варианта исправления и создаёт локальную галерею. Эталон
для нового описания не нужен; автоматическая оценка смысловой правильности без
эталона не выполняется. Для другого описания используйте новую выходную папку.

Скачать точные версии весов на другом компьютере и проверить SHA-256 можно
командой `python tools/download_models.py`. Сохранённая галерея и готовые материалы
защиты работают без скачивания весов. Лицензии моделей указаны отдельно в
`configs/model_lock.json`; они различаются по репозиториям.

## Экспериментальные режимы

| Режим | Источник обратной связи редактору |
|---|---|
| B0 | Исходная генерация, без исправления |
| B1 | Программные проверки исходной схемы |
| B2 | Разбор исходного изображения визуальной моделью |
| B3 | Оба источника |
| C0 (post-test) | Редактирование B0 без внешней критики |
| L3 (post-test) | Сохранённые оба источника; программа разрешает менять только координаты |

Все три исправления используют одну и ту же исходную схему B0. Один визуальный
разбор переиспользуется в B2/B3; исходная генерация и визуальный разбор учитываются
в стоимости каждого самостоятельного режима, а общий расход считает каждый
сохранённый вызов ровно один раз. Редактор может ухудшить результат — это измеряемый
результат, а не повод автоматически заменить его исходной схемой.

## Окружение и модели

Проверенное локальное окружение: Python 3.12, `llama-cpp-python==0.3.36` с CPU
библиотекой MTMD, Pillow и matplotlib. Базовые зависимости перечислены в
`requirements.txt`; llama-cpp-python — отдельная необязательная зависимость
для нового инференса. Скрипты **ничего не устанавливают автоматически**.

| Роль | Файл в `models/` |
|---|---|
| Генератор и редактор основного запуска | `qwen2.5-3b-instruct-q4_k_m.gguf` |
| Предварительный development / smoke-вариант | `qwen2.5-1.5b-instruct-q4_k_m.gguf` |
| Визуальный критик | `SmolVLM-256M-Instruct-Q8_0.gguf` |
| Визуальный проектор | `mmproj-SmolVLM-256M-Instruct-f16.gguf` |

Источники весов: [Qwen 3B GGUF](https://huggingface.co/Qwen/Qwen2.5-3B-Instruct-GGUF),
[Qwen 1.5B GGUF](https://huggingface.co/Qwen/Qwen2.5-1.5B-Instruct-GGUF),
[SmolVLM GGUF и проектор](https://huggingface.co/ggml-org/SmolVLM-256M-Instruct-GGUF).
Исходная визуальная модель: [HuggingFaceTB/SmolVLM-256M-Instruct](https://huggingface.co/HuggingFaceTB/SmolVLM-256M-Instruct).
Ревизии, размеры, сведения об установке и реальные smoke-тесты описаны в
`runtime_setup/HANDOFF.md`. Файл с расширением `.part` ещё не является готовыми весами.
Модели загружаются последовательно; скорость зависит от CPU и свободной RAM.

Для переноса проекта на другой компьютер сначала подготовьте Python-окружение,
установите зависимости и скопируйте/скачайте веса из указанных источников.
Проверить текущее окружение можно без загрузки весов:

```powershell
./.venv/Scripts/python.exe -c "import PIL, matplotlib, llama_cpp; print(llama_cpp.__version__)"
```

## Пересчитать анализ без инференса

Дополнительный анализ шести режимов и новая офлайн-галерея:

```powershell
$env:PYTHONPATH = 'src'
./.venv/Scripts/python.exe -m flowrefine.followup_analysis --baseline runs/test_v1 --followup runs/followup_v1 --layout-followup runs/layout_v2 --output analysis/followup_v1
./.venv/Scripts/python.exe tools/build_followup_gallery.py
Invoke-Item ./demo/followup.html
```

Таблицы изменений, точных исправлений и регрессий находятся в
`analysis/followup_v1/SUMMARY.md`; подробные примеры — в `CASE_STUDIES_RU.md`,
а описательный автоматический аудит критика — в `CRITIC_AUDIT_RU.md`.
Кандидатные утверждения из текста не являются полной оценкой precision/recall критика.

Для **нового** C0-инференса используется отдельная папка:

```powershell
./.venv/Scripts/python.exe -m flowrefine.followup --baseline runs/test_v1 --output runs/followup_NEW --modes C0
```

C0 получает исходный запрос и B0. Это контроль редактирования без внешних замечаний,
а не независимая генерация; формулировка завершающей инструкции также немного отличается
от B1-B3. L3 переиспользует исходную программную и визуальную критику. Программа
строит сцену из B0, принимая от модели только координаты: сохранение логики обеспечено
кодом, а исходно неверные связи таким режимом не исправить. Формат и длина ответа
отличаются от свободного редактора, поэтому разницу затрат нельзя объяснять только критикой.

Первая версия формата координат L3 дала 8 сохранённых невалидных результатов
после 16 вызовов с повторами. Девятый ответ был прерван до записи; его время и токены
неизвестны. Ошибки сохранены в `runs/followup_v1`, а итоговый L3 использует отдельно
пересмотренный после проверки development формат из `runs/layout_v2`. Все записанные
затраты учитываются; общий расход с прерванным вызовом известен лишь снизу.
Для нового запуска пересмотренного формата:

```powershell
./.venv/Scripts/python.exe -m flowrefine.layout_followup --baseline runs/test_v1 --output runs/layout_NEW --failed-run runs/followup_v1
```

Сборка дополнительного отчёта требует `reportlab`; сборка презентации использует
предоставленный средой `@oai/artifact-tool`. Скрипты `tools/build_followup_report.py`,
`tools/build_followup_deck.mjs` и `tools/package_followup.py` используют сохранённые
результаты и не запускают модели. Презентация и архив требуют нового выходного файла;
исходные материалы не перезаписываются.

```powershell
$env:PYTHONPATH = 'src'
./.venv/Scripts/python.exe -m flowrefine.cli analyze runs/test_v1 --output analysis/test_v1
./.venv/Scripts/python.exe -m flowrefine.cli gallery runs/test_v1 --output demo/index.html
```

Анализ использует сохранённые ответы и эталонные графы; генератор и критики
эталоны не читают. Повторный анализ не вызывает модели. Он создаёт `metrics.csv`,
`raw_calls.csv`, `aggregate.json`, `SUMMARY.md` и три PNG-графика.

## Запустить или продолжить CPU-инференс

```powershell
$env:PYTHONPATH = 'src'
./.venv/Scripts/python.exe -m flowrefine.cli run --split test --output runs/test_v1 --model models/qwen2.5-3b-instruct-q4_k_m.gguf --vision-model models/SmolVLM-256M-Instruct-Q8_0.gguf --vision-projector models/mmproj-SmolVLM-256M-Instruct-f16.gguf --phase all
```

Вспомогательные `run_cpu.ps1` и `launch_demo.ps1` доступны, если политика
PowerShell разрешает локальные скрипты. На исходном компьютере выполнение `.ps1`
по умолчанию запрещено; прямые Python-команды выше работают без изменения этой
политики. Примеры параметров помощника ниже эквивалентны флагам CLI.

По умолчанию используется тестовая выборка и `runs/test_v1`. Уже завершённые
компоненты пропускаются. Возобновление разрешено только с теми же настройками,
задачами, версиями промптов и исходного кода инференса. При изменении источников
проверка manifest останавливает запуск; задайте **новую папку**, не удаляйте
старые доказательства эксперимента:

```powershell
./run_cpu.ps1 -RunDir runs/test_v2
```

Для другой текстовой модели задайте `-TextModel models/your-model.gguf` и новую
папку запуска. Аналогично доступны `-VisionModel` и `-VisionProjector`.
Фактическая модель каждого сохранённого эксперимента указана в его manifest
и исходных журналах; примеры установки весов не определяют результаты опыта.

Пробный прогон на двух development-задачах, не тестовых:

```powershell
./run_cpu.ps1 -Split development -Limit 2 -RunDir runs/my_cpu_probe -AnalysisDir analysis/my_cpu_probe -GalleryPath demo/my_cpu_probe.html
```

Можно выполнять фазы последовательно, сохраняя остальные параметры одинаковыми:

```powershell
./run_cpu.ps1 -Phase generate
./run_cpu.ps1 -Phase critique
./run_cpu.ps1 -Phase repair
```

Во время промежуточных фаз анализ честно показывает ещё не исполненные режимы.
Если предыдущий модельный вызов завершился исключением, сохранённый журнал не
перезаписывается: устраните причину и используйте новую папку запуска.

Полная эквивалентная команда:

```powershell
$env:PYTHONPATH = 'src'
./.venv/Scripts/python.exe -m flowrefine.cli run --split test --output runs/test_v1 --model models/qwen2.5-3b-instruct-q4_k_m.gguf --vision-model models/SmolVLM-256M-Instruct-Q8_0.gguf --vision-projector models/mmproj-SmolVLM-256M-Instruct-f16.gguf --phase all
```

Остановка через Ctrl+C сохраняет уже записанные результаты. Частичные файлы
запуска не являются завершённым экспериментом. При воспроизведении изменённый
абсолютный путь к весам также изменяет настройки manifest: на другом компьютере
сохранённые результаты можно анализировать, а новый инференс проводить в новой
папке.

## Данные, метрики и пределы выводов

Датасет — **20 синтетических заданий**, подготовленных ассистентом: 5 development
и 15 test (по 5 цепочек, ветвлений и циклов), 6–7 узлов. Описания получены фиксированным
шаблоном из заранее написанных спецификаций. Темы различаются между выборками,
семейства структур повторяются. Это небольшой pilot на известных шаблонах,
а не независимый человеческий benchmark свободных описаний.

Сопоставление этапов требует совпадения названия и типа после нормализации
регистра, пунктуации и пробелов; перефразирование может снизить оценку даже при
сохранении смысла. Prompts явно требуют сохранять названия. Проверяются node F1,
направленные связи с подписями (edge F1), полное совпадение семантического графа,
геометрические ошибки, валидность, покрытие и затраты модельного инференса.
Подробности: `data/DATASET_CARD.md`.

Программный критик проверяет геометрию и формат, **не смысл процесса**. Маленький
SmolVLM может неправильно читать связи и давать общие замечания. Геометрия не
эквивалентна человеческой читаемости; часть проверок использует консервативные
ограничивающие прямоугольники. Человеческое исследование читаемости не проведено.
Bootstrap-интервалы на 15 задачах не устраняют ограничение малого шаблонного
набора. Сравнение исправления с повторной независимой генерацией здесь не
реализовано; преимущества именно обратной связи над дополнительной попыткой
не следует утверждать.

Некорректный исполненный ответ получает нулевую семантическую оценку, но его
геометрия считается неопределённой. Неисполненный режим остаётся отсутствующим.
Время — зарегистрированное модельное время, включая первое ленивое чтение весов;
валидация, рендеринг и работа пользователя в него не входят.

```text
src/flowrefine/        # формат, рендеринг, критики, CPU-бэкенды, runner, анализ
```

`PLAN.md` описывает принятый объём работы, а фактический статус нужно проверять
по `PROGRESS.md` и сохранённым артефактам. План сам по себе не доказывает выполнение.
